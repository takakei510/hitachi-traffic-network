# Open Campus Guide

## 説明の主軸

展示では、日立周辺の道路ネットワークに対して、どこを壊すと障害が連鎖するかを比較できることを示す。今回の実装では、ランダム故障を複数回試行して平均と標準偏差を出し、高負荷ノード故障と並べて見せられる。

## 見せ方

1. まず `python -m hitachi_network` で解析を実行できることを伝える。
2. ランダム故障は 10 回の試行平均と標準偏差で表示できることを示す。
3. 高負荷ノード故障は 1 回の比較条件として表示する。
4. 結果として CSV、JSON、PNG を保存できることを見せる。
5. PNG で `remaining_nodes` または `largest_component_size` を選択表示し、どちらの破壊が連鎖を起こしやすいかを説明する。

## 現在のデモで伝える内容

- CLI で一括実行できる。
- カスケード故障は `C_i = (1 + alpha) * L_i(0)` に基づく容量超過の繰り返しで進む。
- 各ステップで `remaining_nodes` と `largest_component_size` を記録する。
- このデータではランダム故障の平均の方が高負荷ノード故障より被害が大きく見えた。誤りとして調整せず、そのまま結果として示す。
- 出力は `outputs/cascade_verified/` のようなディレクトリにまとめられる。
