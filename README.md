# Hitachi Traffic Network

日立市周辺の道路ネットワークを用いて、複雑ネットワーク上のカスケード故障を可視化・分析するための Python プロジェクトです。

本プロジェクトでは、道路ネットワークをグラフとして扱い、交差点などの地点をノード、道路をエッジとして表現します。あるノードが故障したときに、残ったネットワーク上で負荷が再配分され、容量を超えたノードがさらに故障していく過程をシミュレーションします。

> このシステムは、実際の交通量・信号制御・車両挙動を厳密に再現する交通流シミュレータではありません。複雑ネットワーク理論に基づく簡易カスケード故障モデルとして、故障の広がり方やネットワーク分断の様子を観察するためのものです。

---

## 現在できること

- 日立市周辺の道路ノード CSV・道路エッジ CSV の読み込み
- NetworkX グラフの生成
- 検索地点を中心とした部分グラフの抽出
- OpenStreetMap Nominatim を用いた場所検索
- OpenStreetMap 背景付きの道路ネットワークプレビュー
- 初期故障ノードの選択
  - 候補ノードから選択
  - ランダム故障
  - 高負荷ノード故障
- 媒介中心性または次数によるノード負荷の計算
- Motter-Lai 型を参考にした簡易カスケード故障計算
- ステップごとの故障進行の確認
- 各ステップの故障ノード数、残存ノード数、最大連結成分の確認
- 結果地図・結果表・処理時間の表示
- Matplotlib による日本語対応済み結果画像の生成

## カスケード故障モデル

### 基本的な考え方

各ノードには、初期状態における負荷と、その負荷に対する容量を与えます。

ノード `i` の初期負荷を `L_i(0)`、容量を `C_i` とすると、容量は次の式で定義します。

```text
C_i = (1 + alpha) L_i(0)
```

`alpha` は容量の余裕を表すパラメータです。

例えば `alpha = 0.20` の場合、初期負荷の 1.2 倍まで耐えられる容量を持つと解釈します。

```text
初期負荷 = 1.00
alpha = 0.20
容量 = 1.20
```

故障後に再計算された負荷が容量を超えると、そのノードは新たに故障します。

```text
再計算後の負荷 > 容量
```

### シミュレーションの流れ

```text
Step 0
初期故障ノードを取り除く

↓

残ったネットワーク上で負荷を再計算

↓

容量を超えたノードをまとめて故障させる

↓

Step 1

↓

再び負荷を再計算

↓

新たな容量超過ノードをまとめて故障させる

↓

Step 2, Step 3, ...

↓

新しい故障ノードが発生しなくなったら終了
```

### ステップ数の意味

ステップ数は、故障したノードの総数ではありません。

1 回の負荷再計算で複数ノードが同時に容量超過した場合、それらは同じステップで故障します。

例えば次のような場合、カスケードステップ数は 3 です。

```text
Step 0: 初期故障 1 ノード
Step 1: 新たに 12 ノード故障
Step 2: 新たに 25 ノード故障
Step 3: 新たに 4 ノード故障
```

このとき故障ノード総数は 42 ですが、カスケードステップ数は 3 です。

## ノード負荷の定義

### betweenness

媒介中心性をノード負荷として使用します。

媒介中心性は、多くの最短経路がそのノードをどれだけ通過するかを表す指標です。

道路ネットワークでは、複数の経路をつなぐ重要な交差点ほど媒介中心性が高くなりやすいため、本プロジェクトでは標準設定として使用しています。

```text
load_model = betweenness
```

#### 解釈

- 値が大きいノード: 多くの最短経路が通る重要地点
- 値が小さいノード: 代替経路への影響が比較的小さい地点

ただし、ここでの媒介中心性は実際の交通量そのものではありません。

### degree

次数をノード負荷として使用します。

次数は、そのノードに接続している道路数を表します。

```text
load_model = degree
```

媒介中心性より高速に計算できますが、ネットワーク全体を通る経路の集中度は表現しにくくなります。

## シミュレーション設定

Streamlit の左側サイドバーで次の値を設定します。

### alpha

ノード容量の余裕を指定します。

```text
C_i = (1 + alpha) L_i(0)
```

設定範囲:

```text
0.00 ～ 1.00
```

意味:

- 小さい値: 容量の余裕が小さく、連鎖故障が起こりやすい
- 大きい値: 容量の余裕が大きく、連鎖故障が起こりにくい

例:

```text
alpha = 0.00  初期負荷と同じ容量
alpha = 0.20  初期負荷の 1.2 倍
alpha = 0.50  初期負荷の 1.5 倍
alpha = 1.00  初期負荷の 2.0 倍
```

展示時の基準値:

```text
alpha = 0.20
```

### load_model

負荷の計算方法を選択します。

```text
betweenness
```

- 媒介中心性を負荷として使う
- 道路ネットワークの重要地点を表現しやすい
- 標準設定

```text
degree
```

- 接続道路数を負荷として使う
- 計算が速い
- 経路集中の表現は簡易的

### sample_size

媒介中心性を近似計算するときに使用するサンプルノード数です。

現在の選択肢:

```text
8
32
100
```

特徴:

- `8`: 高速、展示向け、結果にばらつきが出やすい
- `32`: 速度と安定性のバランス
- `100`: 比較的安定するが、計算時間が増える

グラフのノード数が `sample_size` 以下の場合は、全ノードを使って媒介中心性を計算します。

展示時の推奨:

```text
sample_size = 8 または 32
```

比較実験時の推奨:

```text
sample_size と seed を固定する
```

### seed

ランダム処理を再現するための乱数シードです。

主に次の処理へ影響します。

- ランダム故障ノードの選択
- 近似媒介中心性で使用するサンプルノードの選択

同じネットワーク、同じ設定、同じ `seed` を使用すると、原則として同じ結果を再現できます。

```text
seed = 42
```

`42` 自体に物理的な意味はなく、再現性のための固定値です。

## Streamlit アプリの使い方

### 1. 場所を探す

場所名を入力して `場所を探す` を押します。

例:

```text
日立駅
常陸多賀駅
茨城大学日立キャンパス
```

検索には OpenStreetMap Nominatim を使用します。

候補が複数ある場合は、緯度・経度付きの候補一覧から選択します。

検索結果の下には Google Maps で同じ地点を開くリンクも表示されます。

### 2. 範囲を選ぶ

検索地点を中心とした半径を選びます。

```text
500 m
1 km
2 km
3 km
```

青い円はシミュレーション対象範囲を表します。

#### 部分グラフ

検索地点から指定半径以内にあるノードだけを取り出してシミュレーションします。

展示や短時間の計算では、通常はこちらを使います。

#### 全体グラフ

読み込んだ道路ネットワーク全体を対象にします。

計算量が大きくなるため、設定によっては処理に時間がかかります。

### 3. 故障地点を選ぶ

#### 候補ノード選択

一覧から故障ノードを直接選択します。

ノード ID と緯度・経度が表示されます。

#### ランダム故障

対象グラフから 1 ノードをランダムに選びます。

同じ `seed` を指定すると同じノードが選ばれます。

#### 高負荷ノード故障

初期負荷が最も高いノードを選びます。

`load_model = betweenness` の場合、多くの最短経路が通る重要地点が選ばれます。

### 4. シミュレーションを実行

`シミュレーションを実行` を押します。

内部では次の処理を行います。

```text
道路データ読み込み
↓
対象範囲の部分グラフ抽出
↓
初期負荷計算
↓
初期故障ノード除去
↓
負荷再計算
↓
容量超過ノード除去
↓
故障がなくなるまで反復
↓
結果地図・結果表生成
```

### 5. カスケードの進行を確認

シミュレーション後に、ステップスライダーと前後ボタンが表示されます。

```text
Step 0
Step 1
Step 2
...
最終 Step
```

表示切替時には、カスケード計算そのものは再実行しません。

保存済みの `failed_by_step` を使い、そのステップまでの表示だけを再生成します。

## 結果地図の見方

結果地図では次の色分けを使用します。

- オレンジの星: 検索中心
- 黒: 初期故障ノード
- 濃い赤: 現在のステップで新たに故障したノード
- 薄い赤: 過去のステップですでに故障したノード
- 灰色の線: 道路ネットワーク
- 青い円: シミュレーション範囲

現在の結果画像では、故障の広がりを見やすくするため、正常ノードは基本的に描画していません。

### Step 0

初期故障ノードのみが黒で表示されます。

### Step 1 以降

- そのステップで新しく故障したノード: 濃い赤
- それ以前に故障したノード: 薄い赤
- 初期故障ノード: 黒

この表示により、カスケード故障がどの方向へ広がったかを確認できます。

## 表示される主な指標

### 初期ノード数

シミュレーション開始時の対象ノード数です。

```text
initial_nodes
```

### 残存ノード数

選択中のステップまでに故障していないノード数です。

```text
surviving_nodes = initial_nodes - cumulative_failed_count
```

画面上では既存実装との互換性のため `最終残存ノード数` と表示される場合がありますが、ステップ表示時には選択中ステップの残存数として解釈します。

### このステップで新たに故障

選択中のステップで新しく容量超過したノード数です。

```text
new_failed_count
```

Step 0 では初期故障ノード数を表します。

### 累積故障数

Step 0 から選択中ステップまでに故障したノードの合計です。

```text
cumulative_failed_count
```

### 最大連結成分サイズ

故障ノードを除去した後に残る連結成分のうち、最も大きい成分のノード数です。

```text
largest_component_size
```

値が小さいほど、ネットワークが細かく分断されている可能性があります。

### 最大連結成分比

初期ノード数に対する最大連結成分サイズの割合です。

```text
largest_component_ratio = largest_component_size / initial_nodes
```

例:

```text
0.90  ネットワークの大部分がつながっている
0.50  半分程度しか最大成分に残っていない
0.10  強く分断されている
```

ただし、どの値をもって「壊滅的」と判断するかは研究目的やネットワーク構造によって異なります。

### カスケードステップ数

現在表示しているステップ番号です。

最終ステップで確認した場合は、初期故障後に何回追加故障が発生したかを表します。

## 結果表

結果表には、選択中ステップまでに故障したノードが表示されます。

主な列:

- `node_id`: 道路ネットワーク上のノード ID
- `lon`: 経度
- `lat`: 緯度
- `status`: 内部状態名
- `status_label`: 日本語表示名
- `display_label`: 座標と近隣道路名

`status` の例:

```text
initial_failure
current_step_failure
cascade_failure
```

意味:

- `initial_failure`: 初期故障
- `current_step_failure`: 現在のステップで新たに故障
- `cascade_failure`: 過去のステップで故障済み

## 現在のモデルの限界

本モデルでは、次の要素は直接扱っていません。

- 実測交通量
- 出発地・目的地ごとの OD 需要
- 車線数
- 制限速度
- 信号制御
- 渋滞による所要時間変化
- 時刻別交通量
- 道路容量の実測値
- 車両の動的移動
- 運転者の経路選択行動

また、媒介中心性を負荷とみなすため、負荷は実交通量ではなく、ネットワーク上の経路集中度を表す近似指標です。

したがって、結果は

```text
この交差点が実際に事故で必ず故障する
```

という予測ではなく、

```text
この簡易モデルでは、このノードの除去がネットワーク構造へ大きな影響を与える
```

という構造的な示唆として解釈します。
