# Hitachi Traffic Network

日立市周辺の道路ネットワークを用いて、複雑ネットワーク上のカスケード故障を可視化・分析する Streamlit アプリです。

公開版:

```text
https://hitachi-traffic-network.streamlit.app/
```

このプロジェクトには、次の2種類のカスケード故障モデルがあります。

- **Node Capacity Cascade**: 交差点などのノードが故障するモデル
- **Road Capacity Cascade**: 道路エッジが容量超過によって故障するモデル

> 本アプリは、実測交通量・信号制御・車両挙動を厳密に再現する交通流シミュレータではありません。道路ネットワークの構造、最短経路の集中、道路長、車線数などを用いて、故障の広がり方やネットワーク分断を観察する簡易モデルです。

# 1. Node Capacity Cascade

## 1.1 概要

Node Capacity Cascadeは、交差点などのノードへ負荷と容量を与え、容量を超えたノードが連鎖的に故障するモデルです。

ノード`i`の初期負荷を`L_i(0)`、容量を`C_i`とすると、基本容量は次の式で定義します。

```text
C_i = (1 + alpha) L_i(0)
```

`alpha`は、初期負荷に対してどの程度の余裕を持たせるかを表します。

```text
alpha = 0.20  → 初期負荷の1.2倍
alpha = 0.50  → 初期負荷の1.5倍
alpha = 1.00  → 初期負荷の2.0倍
```

## 1.2 ノード負荷

### betweenness

ノード媒介中心性を負荷として使用します。

多くの最短経路が通る交差点ほど高負荷になります。

### degree

ノード次数を負荷として使用します。

接続道路数に基づくため高速ですが、ネットワーク全体の経路集中は表現しにくくなります。

## 1.3 故障の流れ

```text
Step 0: 初期故障ノードを削除
↓
残ったグラフで負荷を再計算
↓
容量超過ノードを同時に削除
↓
Step 1
↓
新しい容量超過ノードがなくなるまで反復
```

1回の再計算で複数ノードが容量超過した場合、それらは同じStepで故障します。

# 2. Road Capacity Cascade

## 2.1 概要

Road Capacity Cascadeは、道路エッジへ負荷と容量を与え、容量超過した道路が通行不能になるモデルです。

初期故障道路を取り除いた後、残った道路網でエッジ媒介中心性を再計算し、容量を超えた道路を同時に削除します。

```text
初期道路故障
↓
経路の再配分
↓
別の道路へ負荷集中
↓
容量超過道路が故障
↓
再び経路を再計算
```

## 2.2 道路負荷

道路負荷には、道路長を経路コストとしたエッジ媒介中心性を使用します。

```python
nx.edge_betweenness_centrality(
    graph,
    weight="length",
)
```

媒介中心性が高い道路は、多くの最短経路に利用される重要道路と解釈します。

ただし、この負荷は実測交通量そのものではありません。

## 2.3 道路容量

現在の容量式は次です。

```text
C_e = L_e(0) × (1 + alpha) × f_length × f_lanes
```

- `L_e(0)`: 初期エッジ負荷
- `alpha`: 全道路に共通する基本容量余裕
- `f_length`: 道路長補正
- `f_lanes`: 車線数補正

### 道路長補正

```text
f_length = 1 + w_length × max(length / mean_length - 1, 0)
```

平均道路長より長い道路だけに追加容量を与えます。

短い道路の容量が初期負荷未満にならないよう、道路長補正は容量を減らしません。

### 車線数補正

```text
f_lanes = 1 + w_lanes × max(effective_lanes - 1, 0)
```

標準設定の`w_lanes = 0.5`では、次の倍率になります。

```text
実効1.0車線 → ×1.00
実効2.0車線 → ×1.50
実効2.5車線 → ×1.75
実効3.0車線 → ×2.00
```

車線数補正はサイドバーからON/OFFできます。

# 3. 車線数の扱い

## 3.1 OSMのlanes値

道路CSVの`lanes`属性を利用します。

単一値はそのまま総車線数として解釈します。

```text
lanes=1 → 総車線数1
lanes=2 → 総車線数2
lanes=4 → 総車線数4
```

## 3.2 複数値

`3,2`のような複数値は、各方向の車線数として解釈し、合計します。

```text
3,2 → 3 + 2 = 5車線
2,4 → 2 + 4 = 6車線
2,1 → 2 + 1 = 3車線
```

## 3.3 一方通行と双方向

### 一方通行

総車線数をそのまま実効車線数として使用します。

```text
oneway=True, lanes=2
→ 実効車線数2
```

### 双方向

総車線数を2で割り、方向ごとの実効車線数に変換します。

```text
oneway=False, lanes=2
→ 実効車線数1

oneway=False, lanes=3,2
→ 総車線数5
→ 実効車線数2.5
```

実効車線数は最低1車線とします。

## 3.4 lanes欠損時

`lanes`が欠損している場合は、`highway`属性から保守的に推定します。

```text
motorway / trunk → 方向ごと2車線相当
その他           → 方向ごと1車線相当
```

結果表では、車線数の根拠を次のように表示します。

```text
OSM lanes
OSM lanes複数値を合計
OSM lanes・双方向補正
highwayから推定
```

# 4. Road Capacity設定

## alpha（基本容量余裕）

設定範囲:

```text
0.00〜1.00
```

標準値:

```text
0.50
```

```text
alphaが小さい → 故障しやすい
alphaが大きい → 故障しにくい
```

`0.50`は、現在の日立市道路ネットワークでカスケードの進行を観察しやすくするためのデモ用標準値です。実測道路容量から校正した値ではありません。

## 道路長の影響 w

```text
0.0 → 道路長補正なし
0.5 → 標準
値を大きくする → 長い道路がより壊れにくい
```

## 車線数補正を使用する

```text
ON  → 車線数を容量へ反映
OFF → 車線数を無視
```

ON/OFFを切り替えることで、車線数補正の有無を比較できます。

## 車線数の影響 w_n

```text
0.0 → 車線数による追加容量なし
0.5 → 標準
値を大きくする → 多車線道路がより壊れにくい
```

## 媒介中心性の計算精度

```text
高速（32ノード）
標準（64ノード）
高精度（128ノード）
厳密計算
```

推奨:

```text
500 m〜1 km → 標準、高精度、厳密計算
2 km        → 標準または高精度
3 km        → 高速または標準
5 km        → 高速または標準
```

5 kmで128ノードまたは厳密計算を選んだ場合、Webアプリでは処理時間とメモリ使用量を抑えるため、64ノードへ自動制限します。

## seed

ランダム道路選択と近似媒介中心性の再現性を確保する値です。

標準値:

```text
42
```

同じ場所・半径・初期故障道路・パラメータ・seedを使うことで、原則として同じ結果を再現できます。

# 5. アプリの使い方

## 5.1 ページを選ぶ

Streamlit左側のページ一覧から、利用するモデルを選択します。

```text
Hitachi Traffic Network       Node Capacity Cascade
Road Capacity Cascade         Road Capacity Cascade
```

## 5.2 場所を検索する

場所名を入力し、`場所を探す`を押します。

例:

```text
日立駅
常陸多賀駅
茨城大学日立キャンパス
```

## 5.3 対象範囲を選ぶ

Road Capacity Cascadeでは次の範囲を選択できます。

```text
500 m
1 km
2 km
3 km
5 km
```

## 5.4 初期故障道路を選ぶ

次の方法があります。

### 高負荷道路

初期エッジ媒介中心性が最も高い道路を自動選択します。

### ランダム道路

`seed`に基づいて道路をランダム選択します。

### 候補から選択

道路一覧から選びます。

候補には、始点・終点・道路長・元の`lanes`が表示されます。

### 地図から選択

1. `初期故障道路の選び方`で`地図から選択`を選ぶ
2. 地図上の道路中央に表示された半透明ポイントをクリック
3. 選択道路が黒線で強調されることを確認
4. `Road Capacity Cascadeを実行`を押す

場所や半径を変更した場合、以前選択した道路はリセットされます。

## 5.5 シミュレーションを実行する

`Road Capacity Cascadeを実行`を押します。

計算中は、エッジ媒介中心性の計算とカスケード反復を行います。

## 5.6 Stepを切り替える

結果表示後、Stepスライダーで進行を確認できます。

```text
Step 0 → 初期故障道路
Step 1 → 1回目の再計算で故障した道路
Step 2 → 2回目の再計算で故障した道路
...
```

カスケードが発生しなかった場合はStep 0のみ表示し、スライダーは表示しません。

# 6. 地図の見方

## 負荷率ヒートマップ

道路の色は、現在の負荷率を表します。

```text
負荷率 = 現在負荷 / 容量
```

色分け:

```text
水色       0.0〜0.4   余裕あり
青緑       0.4〜0.7   比較的安全
黄色       0.7〜0.9   負荷上昇
オレンジ   0.9〜1.0   故障寸前
赤         1.0超      容量超過
```

故障道路:

```text
黒             初期故障道路
濃いピンク     現在Stepで故障した道路
半透明の灰色   過去Stepですでに故障した道路
```

地図上へマウスを重ねると、道路ID、道路長、元の`lanes`を確認できます。

# 7. 表示される指標

## このStepの新規故障道路

現在表示しているStepで新たに故障した道路数です。

Step 0では初期故障道路数を表します。

## 累積故障道路

Step 0から現在Stepまでに故障した道路の合計です。

## 残存道路

現在Stepの故障道路を除いた後に残っている道路数です。

## 最大連結成分ノード数

残存グラフにおける最大連結成分のノード数です。

この値が小さくなるほど、道路ネットワークが分断されていると解釈できます。

## 最大負荷率

現在Stepで残っている道路のうち、最も高い負荷率です。

## 容量超過道路数

現在Stepの負荷再計算で容量を超えた道路数です。

# 14. 現在のモデルで直接扱っていないもの

- 実測交通量
- 時間帯別交通量
- OD交通需要
- 信号制御
- 道路幅
- 実際の交通容量
- 渋滞速度
- 車両の移動
- 事故復旧時間
- 道路閉鎖時間
- 災害強度
- 人口や避難需要

したがって、結果は「実際にこの道路が必ず故障する」という予測ではありません。

道路ネットワークの構造、最短経路の集中、道路長、車線数を使って、どのように負荷が再配分され、故障が伝播しうるかを見る簡易モデルです。
