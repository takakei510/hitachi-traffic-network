# Hitachi Traffic Network

日立市周辺の道路ネットワークを用いて、複雑ネットワーク上のカスケード故障を可視化・分析するための Python プロジェクトです。

本プロジェクトでは、道路ネットワークをグラフとして扱い、交差点などの地点をノード、道路をエッジとして表現します。あるノードが故障したときに、残ったネットワーク上で負荷が再配分され、容量を超えたノードがさらに故障していく過程をシミュレーションします。

> このシステムは、実際の交通量・信号制御・車両挙動を厳密に再現する交通流シミュレータではありません。複雑ネットワーク理論に基づく簡易カスケード故障モデルとして、故障の広がり方やネットワーク分断の様子を観察するためのものです。

---

## 現在できること

- 日立市周辺の道路ノード CSV・道路エッジ CSV の読み込み
- NetworkX グラフの生成
- 検索地点を中心とした部分グラフの抽出
- OpenStreetMap Nominatim を用いた場所検索
- OpenStreetMap 背景付きの道路ネットワークプレビュー
- 初期故障ノードの選択

  - 高負荷ノード故障
- 媒介中心性または次数によるノード負荷の計算
- Motter-Lai 型を参考にした簡易カスケード故障計算
- ステップごとの故障進行の確認
- 各ステップの故障ノード数、残存ノード数、最大連結成分の確認
- 結果地図・結果表・処理時間の表示
- Matplotlib による日本語対応済み結果画像の生成

## カスケード故障モデル

### 基本的な考え方

各ノードには、初期状態における負荷と、その負荷に対する容量を与えます。

ノード `i` の初期負荷を `L_i(0)`、容量を `C_i` とすると、容量は次の式で定義します。

```text
C_i = (1 + alpha) L_i(0)
```

`alpha` は容量の余裕を表すパラメータです。

例えば `alpha = 0.20` の場合、初期負荷の 1.2 倍まで耐えられる容量を持つと解釈します。

```text
初期負荷 = 1.00
alpha = 0.20
容量 = 1.20
```

故障後に再計算された負荷が容量を超えると、そのノードは新たに故障します。

```text
再計算後の負荷 > 容量
```

### シミュレーションの流れ

```text
Step 0
初期故障ノードを取り除く

↓

残ったネットワーク上で負荷を再計算

↓

容量を超えたノードをまとめて故障させる

↓

Step 1

↓

再び負荷を再計算

↓

新たな容量超過ノードをまとめて故障させる

↓

Step 2, Step 3, ...

↓

新しい故障ノードが発生しなくなったら終了
```

### ステップ数の意味

ステップ数は、故障したノードの総数ではありません。

1 回の負荷再計算で複数ノードが同時に容量超過した場合、それらは同じステップで故障します。

例えば次のような場合、カスケードステップ数は 3 です。

```text
Step 0: 初期故障 1 ノード
Step 1: 新たに 12 ノード故障
Step 2: 新たに 25 ノード故障
Step 3: 新たに 4 ノード故障
```

このとき故障ノード総数は 42 ですが、カスケードステップ数は 3 です。

## ノード負荷の定義

### betweenness

媒介中心性をノード負荷として使用します。

媒介中心性は、多くの最短経路がそのノードをどれだけ通過するかを表す指標です。

道路ネットワークでは、複数の経路をつなぐ重要な交差点ほど媒介中心性が高くなりやすいため、本プロジェクトでは標準設定として使用しています。

```text
load_model = betweenness
```

#### 解釈

- 値が大きいノード: 多くの最短経路が通る重要地点
- 値が小さいノード: 代替経路への影響が比較的小さい地点

ただし、ここでの媒介中心性は実際の交通量そのものではありません。

### degree

次数をノード負荷として使用します。

次数は、そのノードに接続している道路数を表します。

```text
load_model = degree
```

媒介中心性より高速に計算できますが、ネットワーク全体を通る経路の集中度は表現しにくくなります。

## シミュレーション設定

Streamlit の左側サイドバーで次の値を設定します。

### alpha

ノード容量の余裕を指定します。

```text
C_i = (1 + alpha) L_i(0)
```

設定範囲:

```text
0.00 ～ 1.00
```

意味:

- 小さい値: 容量の余裕が小さく、連鎖故障が起こりやすい
- 大きい値: 容量の余裕が大きく、連鎖故障が起こりにくい

例:

```text
alpha = 0.00  初期負荷と同じ容量
alpha = 0.20  初期負荷の 1.2 倍
alpha = 0.50  初期負荷の 1.5 倍
alpha = 1.00  初期負荷の 2.0 倍
```

展示時の基準値:

```text
alpha = 0.20
```

### load_model

負荷の計算方法を選択します。

```text
betweenness
```

- 媒介中心性を負荷として使う
- 道路ネットワークの重要地点を表現しやすい
- 標準設定

```text
degree
```

- 接続道路数を負荷として使う
- 計算が速い
- 経路集中の表現は簡易的

### sample_size

媒介中心性を近似計算するときに使用するサンプルノード数です。

現在の選択肢:

```text
8
32
100
```

特徴:

- `8`: 高速、展示向け、結果にばらつきが出やすい
- `32`: 速度と安定性のバランス
- `100`: 比較的安定するが、計算時間が増える

グラフのノード数が `sample_size` 以下の場合は、全ノードを使って媒介中心性を計算します。

展示時の推奨:

```text
sample_size = 8 または 32
```

比較実験時の推奨:

```text
sample_size と seed を固定する
```

### seed

ランダム処理を再現するための乱数シードです。

主に次の処理へ影響します。

- ランダム故障ノードの選択
- 近似媒介中心性で使用するサンプルノードの選択

同じネットワーク、同じ設定、同じ `seed` を使用すると、原則として同じ結果を再現できます。

```text
seed = 42
```

`42` 自体に物理的な意味はなく、再現性のための固定値です。

## Streamlit アプリの使い方

### 1. 場所を探す

場所名を入力して `場所を探す` を押します。

例:

```text
日立駅
常陸多賀駅
茨城大学日立キャンパス
```

検索には OpenStreetMap Nominatim を使用します。

候補が複数ある場合は、緯度・経度付きの候補一覧から選択します。

検索結果の下には Google Maps で同じ地点を開くリンクも表示されます。

### 2. 範囲を選ぶ

検索地点を中心とした解析半径を選びます。

```text
500 m
1 km
2 km
3 km
```

また、次のいずれかを選択します。

- `部分グラフ`: 選択半径内の道路ネットワークのみを対象にする
- `全体グラフ`: 読み込んだ道路ネットワーク全体を対象にする

展示では、計算時間と見やすさの観点から `部分グラフ` を推奨します。

### 3. 故障地点を選ぶ

次の方法から選択します。

#### 候補ノード選択

一覧から故障させたいノードを選びます。

各候補には、ノード ID、緯度、経度が表示されます。

#### ランダム故障

`seed` に基づいて 1 ノードをランダムに選択します。

同じ `seed` を使えば、原則として同じノードが選ばれます。

#### 高負荷ノード故障

初期負荷が最も高いノードを自動選択します。

`load_model = betweenness` の場合は、最も多くの最短経路が通ると推定された重要ノードを故障させます。

### 4. シミュレーションを実行

`シミュレーションを実行` を押します。

内部では、次の処理を行います。

```text
部分グラフ抽出
↓
初期負荷計算
↓
容量設定
↓
初期故障ノード削除
↓
負荷再計算
↓
容量超過ノード削除
↓
新しい故障がなくなるまで反復
```

### 5. カスケードの進行を確認

シミュレーション完了後、ステップスライダーと前後ボタンが表示されます。

- `Step 0`: 初期故障のみ
- `Step 1`: 1 回目の負荷再計算で新たに故障したノード
- `Step 2`: 2 回目の負荷再計算で新たに故障したノード
- 以下同様

ステップを切り替えても、カスケード計算そのものは再実行しません。

保存済みの `failed_by_step` を使って表示だけを再生成します。

## 結果地図の見方

結果地図では、次の色を使用します。

- オレンジの星: 検索中心
- 黒: 初期故障ノード
- 濃い赤: 現在のステップで新たに故障したノード
- 薄い赤: 過去のステップですでに故障したノード
- 青い円: シミュレーション対象範囲
- 薄い灰色の線: 道路ネットワーク

正常ノードは、結果画像では原則として表示しません。

故障の空間的な広がりを見やすくするためです。

---

## 表示される主な指標

### 初期ノード数

シミュレーション開始時点のノード数です。

### 残存ノード数

選択中のステップまでに故障していないノード数です。

### このステップで新たに故障

現在表示しているステップで、容量超過により新しく故障したノード数です。

Step 0 では、初期故障ノード数を表します。

### 累積故障数

Step 0 から現在ステップまでに故障したノードの合計です。

### 最大連結成分サイズ

故障ノードを取り除いた後のネットワークで、最も大きくつながっているノード集合のサイズです。

この値が小さくなるほど、道路ネットワークが細かく分断されていると解釈できます。

### 最大連結成分比

初期ノード数に対する最大連結成分サイズの比率です。

```text
最大連結成分比 = 最大連結成分サイズ / 初期ノード数
```

例:

```text
初期ノード数 = 150
最大連結成分サイズ = 18
最大連結成分比 = 0.120
```

これは、初期ネットワークの 12% に相当する規模の連結部分しか残っていないことを意味します。

### カスケードステップ数

初期故障後に、負荷再計算と追加故障が何段階続いたかを表します。

Step 0 は初期故障なので、最終表示が Step 4 なら、追加故障が 4 段階発生したことを意味します。

## 結果表

結果表には、選択中のステップまでに故障したノードが表示されます。

主な列:

- `node_id`: 道路ネットワーク上のノード ID
- `x` / `lon`: 経度
- `y` / `lat`: 緯度
- `status`: 内部ステータス
- `status_label`: 日本語表示用ステータス
- `display_label`: 座標や近隣道路名を含む表示ラベル

主な `status`:

```text
initial_failure
```

初期故障ノードです。

```text
current_step_failure
```

現在のステップで新たに故障したノードです。

```text
cascade_failure
```

過去のステップですでに連鎖故障したノードです。

- 初期故障ノード
- `load_model`
- `sample_size`

## 現在のモデルで扱っていないもの

現時点では、次の要素を直接扱っていません。

- 実測交通量
- 時間帯別交通量
- OD 交通需要
- 信号制御
- 車線数に基づく道路容量
- 渋滞速度
- 車両の移動
- 事故復旧
- 道路閉鎖時間
- 地形や災害強度
- 人口や避難需要

そのため、結果は「実際にこの道路が必ず壊れる」という予測ではありません。

ネットワーク構造上、どのように故障が伝播しうるかを見る簡易モデルです。

## トラブルシューティング

### 変更が反映されない

Streamlit を停止して再起動します。

```text
Ctrl + C
```

```powershell
git pull
streamlit run app.py
```

必要な場合のみ、Streamlit のメニューからキャッシュを削除します。

### `use_container_width` の警告

新しい Streamlit では、`use_container_width=True` の代わりに `width="stretch"` を使用します。

警告だけの場合は直ちに停止する原因ではありませんが、順次置き換えます。

### 場所検索に失敗する

Nominatim 検索にはインターネット接続が必要です。

検索語をより具体的にすると改善する場合があります。

```text
日立駅 茨城県
茨城大学 日立キャンパス
```

### 結果地図が表示されない

次を確認します。

- Streamlit を完全に再起動したか
- ブラウザを再読み込みしたか
- `outputs` フォルダへ書き込み可能か
- Matplotlib が PNG を生成できているか
